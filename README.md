# Intelligence.TradeSystem

**Intelligence.TradeSystem** — экспериментальный .NET-бэкенд для автоматизации анализа крипторынка.

Система получает рыночные данные с биржи, собирает их в единый структурированный снимок рынка и подготавливает JSON-контекст, который можно передать языковой модели для анализа торговой ситуации.

Проект создаётся как инструмент поддержки принятия решений: он помогает быстрее понять состояние рынка, оценить качество потенциального входа и снизить зависимость от ручного анализа графиков.

---

## Зачем нужен проект

При ручном анализе крипторынка приходится одновременно учитывать:

- цену и её изменение;
- несколько таймфреймов;
- технические индикаторы;
- стакан заявок;
- поток сделок;
- открытый интерес;
- ставку финансирования;
- соотношение лонгов и шортов;
- свежесть и надёжность данных;
- зоны поддержки, сопротивления и ликвидности.

Если передавать языковой модели только скриншот графика, часть контекста теряется: модель видит картинку, но не имеет точных числовых данных, не знает состояние стакана, деривативов и качества источников.

**Intelligence.TradeSystem решает эту проблему иначе:**  
он собирает рыночные данные напрямую из API биржи, рассчитывает необходимые показатели на стороне backend и формирует компактный JSON, пригодный для анализа языковой моделью.

---

## Что делает система

На текущем этапе проект умеет:

- получать рыночные данные с Bybit;
- собирать единый снимок рынка по инструменту;
- анализировать несколько таймфреймов;
- рассчитывать технические индикаторы;
- оценивать рыночный режим;
- определять направление, силу тренда и состояние моментума;
- учитывать стакан заявок и поток сделок;
- учитывать деривативные метрики: funding, open interest, long/short ratio;
- оценивать качество потенциального входа;
- формировать risk-флаги, объясняющие слабые места торговой идеи;
- формировать компактные market tags для быстрого понимания ситуации;
- проверять свежесть данных;
- отдавать результат в JSON-формате, удобном для LLM-анализа.

---

## Основной сценарий использования

Типовой сценарий выглядит так:

1. Пользователь или внешний сервис запрашивает анализ инструмента, например `BTCUSDT`.
2. Backend получает данные с биржи.
3. Система рассчитывает индикаторы и дополнительные рыночные признаки.
4. Формируется структурированный snapshot.
5. Snapshot преобразуется в LLM-ready JSON.
6. JSON передаётся языковой модели.
7. Модель делает вывод: есть ли торговая идея, насколько она качественная, какие риски и какие уровни важны.

Проект находится в активной разработке.

Сейчас основной фокус:

- Bybit;
- линейные фьючерсы;
- intraday-анализ;
- формирование качественного JSON snapshot;

Проект пока не является готовым торговым ботом и не предназначен для полностью автоматического открытия сделок без контроля пользователя.

## Что входит в snapshot

Итоговый JSON содержит несколько смысловых блоков:

- общую информацию об инструменте;
- цену и 24h-диапазон;
- данные деривативов;
- состояние стакана;
- поток сделок;
- анализ таймфреймов;
- состояние индикаторов;
- оценку качества входа;
- риск-флаги;
- рыночные теги;
- состояние свежести данных.

Цель snapshot — дать модели не сырые данные биржи, а уже подготовленный контекст для принятия решения.

---

## Оценка качества входа

Одно из ключевых полей snapshot — `entryQuality`.

Оно отвечает не на вопрос “есть ли тренд?”, а на вопрос:

> Насколько текущая ситуация подходит для рассмотрения входа?

В оценке учитываются:

- направление рынка;
- подтверждение тренда;
- положение цены относительно EMA;
- RSI;
- объём;
- близость к поддержке или сопротивлению;
- уровни старших таймфреймов;
- свежесть данных;
- рыночный режим;
- качество индикаторов;
- конфликтующие сигналы.

Возможные значения:

- `Good` — условия выглядят достаточно качественно;
- `Fair` — идея есть, но подтверждение неполное;
- `Poor` — вход слабый или рискованный.

---

## Risk flags

`riskFlags` объясняют, почему вход может быть плохим или почему качество входа было снижено.

Примеры причин:

- низкий объём;
- перегретый RSI;
- конфликт с EMA;
- слабый тренд;
- цена рядом с сопротивлением;
- рынок находится в нейтральном режиме;
- тренд есть, но вход отфильтрован дополнительными условиями.

Это помогает языковой модели не только увидеть итоговую оценку, но и понять её причину.

---

## Market tags

`tags` — это короткие агрегированные признаки рынка.

Они позволяют быстро понять общий контекст без чтения всего JSON.

Примеры:

- `trending`;
- `volatile-regime`;
- `mean-reversion-regime`;
- `bid-pressure`;
- `aggressive-selling`;
- `orderbook-tradeflow-conflict`;
- `weak-tradeflow-confirmation`;
- `oi-declining`;
- `possible-long-unwinding`;
- `actionable-entry`;
- `weak-entry-confirmation`.

Теги помогают модели быстрее сориентироваться: рынок трендовый или нейтральный, есть ли конфликт сигналов, падает ли open interest, есть ли потенциальная торговая идея.

---

## Режимы анализа

Система поддерживает несколько режимов анализа.

| Режим | Назначение |
|------|------------|
| `Intraday` | Внутридневной анализ и поиск краткосрочных сценариев |
| `Swing` | Более широкий контекст для удержания позиции дольше одного дня |
| `Portfolio` | Оценка состояния рынка в контексте портфеля |

На текущем этапе основной фокус — `Intraday`.

## API

### Таблица endpoint'ов

| Метод | Маршрут | Описание |
|-------|---------|----------|
| `GET` | `/api/market-analysis/{symbol}/llm-payload` | Получение LLM-ready payload. |
| `POST` | `/api/market-analysis/snapshot` | Сырой market snapshot для отладки и проверки данных. |

---

### Получить LLM-ready payload

```http
GET /api/market-analysis/{symbol}/llm-payload
````

Пример:

```http
GET /api/market-analysis/BTCUSDT/llm-payload?exchange=Bybit&category=Linear&mode=Intraday
```

Ответ — JSON snapshot, подготовленный для передачи в языковую модель. Схема `1.0`.

---

### Получить сырой market snapshot

```http
POST /api/market-analysis/snapshot
```

Пример тела запроса:

```json
{
  "exchange": "Bybit",
  "symbol": "BTCUSDT",
  "category": "Linear"
}
```

Этот endpoint полезен для отладки и проверки данных до преобразования в LLM payload.

## Как запустить проект

### Требования

* .NET SDK
* доступ к интернету для получения рыночных данных
* при необходимости — API-ключи Bybit для приватных endpoint’ов

---

### Восстановить зависимости

```bash
dotnet restore Intelligence.TradeSystem.slnx
```

### Собрать проект

```bash
dotnet build Intelligence.TradeSystem.slnx --no-restore
```

### Запустить тесты

```bash
dotnet test Intelligence.TradeSystem.slnx --no-build --logger "console;verbosity=minimal"
```

### Запустить API

```bash
dotnet run --project src/Intelligence.TradeSystem.Api
```

Swagger UI доступен в режиме Development.

## Ограничения

Текущие ограничения проекта:

* основной поддерживаемый источник данных — Bybit;
* проект находится в экспериментальной стадии;
* торговые решения не исполняются автоматически;
* snapshot используется для decision support, а не как самостоятельный торговый сигнал;
* частичные snapshot’ы и агрегированный рыночный контекст ещё развиваются;
* качество анализа зависит от свежести и полноты рыночных данных.
