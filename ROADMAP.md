## 1. Цель проекта

Проект развивается в сторону системы интеллектуального сопровождения уже открытых торговых позиций.

Пользователь открывает сделки самостоятельно, а система:

- получает данные о торговом аккаунте и открытых позициях;
- непрерывно оценивает состояние каждой позиции;
- сопоставляет позицию с текущим состоянием рынка;
- оценивает риск позиции и портфеля;
- формирует рекомендацию по дальнейшим действиям;
- объясняет причины рекомендации;
- отслеживает существенные изменения;
- уведомляет пользователя, когда ситуация требует внимания.

Основные типы рекомендаций:

- `HOLD` — удерживать позицию;
- `WATCH` — наблюдать, ситуация требует внимания;
- `REDUCE` — сократить позицию;
- `EXIT` — закрыть позицию;
- `ADD_ALLOWED` — усреднение допустимо при заданных условиях;
- `DO_NOT_ADD` — усреднять позицию сейчас нельзя.

На первом этапе система является инструментом поддержки принятия решений и не должна самостоятельно исполнять торговые операции.

---

## 2. Архитектурные принципы

- Backend является единственным источником правды для всех клиентов.
- React Web является основным пользовательским интерфейсом.
- Telegram используется прежде всего для уведомлений.
- CLI, Telegram, Web и будущие клиенты работают через один backend и получают одинаковую бизнес-логику.
- Рыночная аналитика отделена от пользовательского портфеля.
- Базовые показатели и ограничения рассчитываются детерминированно на backend.
- LLM используется для рассуждения и объяснения поверх подготовленных данных, а не вместо бизнес-логики.
- LLM не должна обходить ограничения, установленные risk-логикой backend.
- Автоматическое исполнение торговых операций не входит в первый MVP.

# 12. Граница MVP

Первый MVP считается готовым после завершения этапов **0–7**.

Пользователь должен иметь возможность:

1. Подключить торговый аккаунт Bybit.
2. Увидеть открытые позиции в Web.
3. Открыть страницу конкретной позиции.
4. Увидеть её текущее состояние.
5. Получить рекомендацию.
6. Понять причины рекомендации.
7. Увидеть историю изменений.
8. Позволить системе продолжать наблюдение за позицией.
9. Получить Telegram-уведомление при существенном изменении.

Не входят в первый MVP:

- автоматическое открытие сделок;
- автоматическое закрытие сделок;
- полноценная мультибиржевая поддержка;
- мобильные приложения;
- сложная социальная аналитика;
- автоматическая торговая стратегия.

# 19. Правила обновления Roadmap

Этот файл является живым документом.

При изменении проекта:

1. Выполненные задачи отмечаются `[x]`.
2. Новые задачи добавляются в соответствующий этап.
3. Если задача потеряла актуальность, она удаляется или явно помечается как отменённая.
4. После завершения всех обязательных задач этап получает статус `✅ Выполнен`.
5. Текущий активный этап получает статус `🚧 В работе`.
6. После каждого существенного изменения обновляется дата в начале документа.
7. Если архитектурное решение меняет направление проекта, сначала обновляется roadmap, затем реализуется код.
8. Крупные задачи желательно связывать с GitHub Issue или PR.

Рекомендуемый формат ссылки:

```text
- [x] Добавлена синхронизация позиций — #34
```
