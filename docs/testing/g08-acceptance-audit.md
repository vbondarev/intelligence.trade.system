# Issue #225: аудит готовности G-08

Обновлено 19 ноября 2026 года. [Issue #225](https://github.com/vbondarev/intelligence.trade.system/issues/225) · [Approved Plan](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6877298059) · [Amendment по результатам аудита WCAG](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6958879377) · [Обязательный Windows WebKit gate](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6884893121)

Этот документ отделяет наличие реализации от доказанного выполнения критериев. Ручные результаты пользователя учитываются как его сообщение, без приписывания агенту самостоятельного наблюдения. Подробная применимость WCAG — в [матрице](g08-wcag22-aa-matrix.md); протокол ручной проверки — в [инструкции](g08-manual-wcag-protocol.md).

Статус `BLOCKED_BY_VERIFICATION`. Обязательная HTTPS-проверка повторила FAIL Windows mobile WebKit. Сервер отправил session cookie с `SameSite=Lax`, а в cross-site запрос WebKit включил обе cookie. Тест требовал только контрольную cookie.

Проверка официальной сборки Playwright отслеживается в [Issue #226](https://github.com/vbondarev/intelligence.trade.system/issues/226). Для завершения IMP-07 нужны PASS действующего Windows HTTPS gate, полный Windows E2E, все шесть сценариев realtime recovery и предусмотренный Linux CI.

[Amendment о раннем merge](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-7009165810) допускает внешнее ревью и слияние только в `develop` при известном FAIL Windows WebKit. Для слияния обязательны успешный CI и все шесть сценариев realtime recovery на итоговом коммите, завершённое ревью и отдельное решение владельца. Релиз, IMP-07 и закрытие #225 остаются заблокированными до PASS Windows WebKit gate в #226 и подтверждения остальных критериев приёмки.

По Amendment исправлены 8 нарушений WCAG и проверены 5 критериев со статусом PARTIAL. Подтверждены управление графиком, контекст ссылок, поиск и подсказки ошибок. На изолированном Compose прошли все шесть сценариев realtime recovery. Для этого этапа матрица зафиксировала 42 PASS и 14 N/A.

На коммите `28855fe` в GitHub Linux CI пять сценариев в каждом браузере выявили горизонтальное переполнение при viewport 320 CSS px и увеличении текста до 200%. Ширина документа достигала 356 CSS px. Новый тест с широкими метриками текста на прежнем CSS показал 358 CSS px в Windows Chromium и mobile WebKit. После FIX-06 при тех же условиях оба браузера подтвердили укладывание документа, названия и всех ссылок в 320 CSS px и переход на «Обзор» с клавиатуры. Подтверждение всех затронутых сценариев в GitHub CI относится к итоговому коммиту FIX-06. [Исходный Linux FAIL](https://github.com/vbondarev/intelligence.trade.system/actions/runs/44580195971/job/135763118299?pr=227) · [Проверки PR #227](https://github.com/vbondarev/intelligence.trade.system/pull/227/checks)

Полный локальный Windows E2E после FIX-06 дал 102 PASS, 13 SKIP по браузерным конфигурациям и один известный FAIL проверки `SameSite` в mobile WebKit. Все шесть сценариев realtime recovery прошли. Отдельный Windows HTTPS gate повторил 3 PASS и 1 FAIL по cross-site отправке session cookie.

Проверки frontend включили typecheck, lint и 390 unit/component tests. API прошёл 636 тестов, BFF прошёл 361. Два unit-теста поиска подтвердили отмену устаревшего запроса при смене символа и сохранение снимка до возобновления автообновления. Браузерные сценарии Amendment находятся в [wcag-remediation.spec.ts](../../frontend/intelligence-trade-web/e2e/wcag-remediation.spec.ts).

Итоговый E2E на двух отдельных Compose проектах дал 98 PASS, 13 SKIP по браузерным проектам и 1 FAIL. В Chromium прошли 54 из 54 применимых сценариев. В Windows mobile WebKit прошли 44, проверка `SameSite` получила `None` вместо `Lax`. Отдельный HTTPS gate на этой же версии дал 3 PASS и 1 FAIL по поведению session cookie.

При подготовке Draft PR повторили typecheck, lint, 390 unit/component tests и все шесть full-stack realtime E2E. Эти проверки прошли. В HTTPS-тесте переход верхнего уровня начинается щелчком по ссылке с другого сайта. Штатный Windows gate снова дал 3 PASS и 1 FAIL на cross-site отправке session cookie. Локальный Linux-контроль прошёл 4/4.

- Повторно проверены все 26 критериев WCAG со статусом `PARTIAL`. Из них 13 получили `PASS`, 8 — `FAIL`, 5 сохранили `PARTIAL` с конкретными наблюдениями. Повторный полный E2E дал 88 PASS, 11 SKIP по конфигурации и 1 FAIL Windows mobile WebKit. Realtime recovery — 6/6. Отдельный Windows HTTPS gate — 3 PASS, 1 FAIL. [Журнал повторного аудита](g08-wcag22-aa-follow-up.md).
- [Amendment о паузе автообновлений](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6957039001) опубликован и перечитан. Typecheck, lint, Docker build и 388 frontend-тестов прошли. Полный браузерный E2E — 88 PASS, 11 SKIP по конфигурации, 1 FAIL на `SameSite` в Windows mobile WebKit. Realtime recovery — 6/6. Отдельный Windows HTTPS gate — 3 PASS, 1 FAIL.
- Пауза проверена при 320 CSS px и 200% увеличении текста в обоих браузерах. В Chromium при реальном zoom 400% получено 314 CSS px. В Chrome/NVDA наблюдались объявления паузы и возобновления, видимый снимок сохранился после реального outbox-события на паузе. Проверены повтор после ошибки, ручная история, logout при возобновлении и истечение сессии на паузе. [Результаты паузы автообновлений](g08-auto-update-pause-proposal.md).
- После [Amendment о форме входа Identity](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6950802243) Windows Chromium и mobile WebKit завершили вход после 961 секунды на форме (2/2). До POST не было запроса авторизации и correlation/nonce cookies. После одного POST с `303` каждый браузер завершил один свежий challenge `prompt=none` с PKCE. BFF — 361/361, Identity/OIDC — 114/114, frontend — 385/385. Независимый HTTPS gate на новой версии — 3 PASS, 1 FAIL. [Доказательства и границы проверки](g08-identity-login-timing-proposal.md).

- При реальном zoom 400% в Chromium форма входа и экран повтора уместились в viewport шириной 316 CSS px без горизонтального переполнения. После ошибки фокус был на кнопке «Начать вход заново», Enter открыл форму, повтор завершился входом.
- В Windows Chrome Speech Viewer подтвердил озвучивание полей формы, сообщения «Не удалось завершить вход. Начните вход заново» и фокуса на кнопке повтора. Для ошибки использовали реальный ответ после потери Identity SSO между шагами.

## Предыдущие проверки

- [Amendment по WCAG 2.2.1](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6949333752) опубликован и перечитан в Issue #225. - Полный браузерный прогон после реализации — 68 PASS, 11 SKIP, 1 FAIL. Realtime recovery — 4/4. Четыре E2E нового предупреждения отдельно прошли в Chromium и mobile WebKit. При настоящем zoom 400% ширина Chromium составила 314 CSS px. Настоящий POST продлил ticket, фокус вернулся в поле, тестовый черновик сохранился.
- Chrome и NVDA Speech Viewer: фактически объявлены «Сессия скоро завершится, диалог», «Продлите сессию, чтобы сохранить доступ к приложению» и «Продлить сессию, кнопка». Приближение срока в этой проверке воспроизведено тестовым ответом, вход был реальным.
- Реальный короткоживущий стенд с `Bff__Session__Lifetime=00:00:40`: явное продление сдвинуло deadline без reconnect. Затем сессия истекла, старый WebSocket закрылся и не получил тестовое событие. Повторный OIDC-вход восстановил соединение, успешный GET вернул новое синтетическое подключение, записанное через outbox после истечения. Отдельный E2E с удалением временных correlation/nonce cookies прошёл в Chromium и mobile WebKit (2/2).
- HTTPS Windows: 3 PASS, 1 FAIL. Оба теста продления подтвердили CSRF и `Secure`, `HttpOnly`, `SameSite=Lax` в `Set-Cookie`. Исходный cross-site gate WebKit сохранил FAIL. Linux Playwright 1.63.0 в локальном контейнере — 4/4 PASS, включая исходный gate и продление в обоих браузерах.

- Сборка новых Docker-образов frontend и Identity прошла. Typecheck и lint прошли. Ранее 385 unit-тестов и сборка frontend прошли, изменения после них затронули CSS и E2E. Authentication IntegrationTests на реальном PostgreSQL — 107/107 PASS.
- `PositionTimeline.test.tsx` — 39/39 PASS. Проверяется заранее существующая live region для ручных загрузок, очистка после ответа и отсутствие сообщения о фоновом realtime-чтении в ней.
- Полный browser E2E на пересобранных Identity и frontend с исправленным контрастом — **62 PASS, 11 SKIP, 1 FAIL**. Realtime recovery — 4/4. Единственный FAIL — `SameSite=None` вместо `Lax` в Windows mobile WebKit. Повторный чистый прогон заменяет промежуточный, который выполнялся параллельно с изменением контрастного тестового сценария.
- Отдельный прогон Identity и axe/размера целей — 8/8 PASS. Подтверждены `lang=en` у английской фразы, форма при 320×740 и 1440×900, один доступный alert при неверном пароле и успешный OIDC-вход после него в обоих браузерах. Проверка контраста заполненных страниц использует синтетические бизнес-данные.
- Дополнительный прогон Identity и негативных состояний — 8/8 PASS. В обоих браузерах проверены Tab и Shift+Tab на форме при 320 CSS px. После реального входа проверены axe и reflow для загрузки подключений, пустого списка, ответа 503 и недоступной позиции 404 с тестовыми ответами backend.
