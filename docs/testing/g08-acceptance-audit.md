Обновлено 23 ноября 2026 года. [Issue #225](https://github.com/vbondarev/intelligence.trade.system/issues/225) · [Approved Plan](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6877298059) · [Amendment по результатам аудита WCAG](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6958879377) · [Обязательный Windows WebKit gate](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-6884893121)

Этот документ отделяет наличие реализации от доказанного выполнения критериев. Ручные результаты пользователя учитываются как его сообщение, без приписывания агенту самостоятельного наблюдения. Подробная применимость WCAG — в [матрице](g08-wcag22-aa-matrix.md); протокол ручной проверки — в [инструкции](g08-manual-wcag-protocol.md).

Статус `BLOCKED_BY_VERIFICATION`. Обязательная HTTPS-проверка повторила FAIL Windows mobile WebKit. Сервер отправил session cookie с `SameSite=Lax`, а в cross-site запрос WebKit включил обе cookie. Тест требовал только контрольную cookie.

Проверка официальной сборки Playwright отслеживается в [Issue #226](https://github.com/vbondarev/intelligence.trade.system/issues/226). Для завершения IMP-07 нужны PASS действующего Windows HTTPS gate, полный Windows E2E, все шесть сценариев realtime recovery и предусмотренный Linux CI.

[Amendment о раннем merge](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-7009165810) допускает внешнее ревью и слияние только в `develop` при известном FAIL Windows WebKit. Для слияния обязательны успешный CI и все шесть сценариев realtime recovery на итоговом коммите, положительное заключение о готовности с учётом утверждённой отсрочки и отдельное решение владельца. [Amendment об отсрочке замечаний](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-7027586013) применяется только к раннему слиянию. Релиз, IMP-07 и закрытие #225 остаются заблокированными до PASS Windows WebKit gate в #226 и подтверждения остальных критериев приёмки.

## Клавиатурная проверка продолжения истории

23 ноября 2026 года проверена локальная правка поверх `develop` @ `743ea5ea29266eb493927b0be5a3fa66064555a8`. Обе [компонентные регрессии](../../frontend/intelligence-trade-web/src/position/PositionTimeline.test.tsx) до исправления зафиксировали переход фокуса на `BODY`. После исправления прошли все 519 frontend unit/component-тестов, typecheck, lint и build.

В Playwright 1.63.0 на Windows прошли четыре изолированных браузерных сценария при ширине 320 CSS px: по два в Chromium 153.0.8010.12 и WebKit 26.6. С помощью Tab и Enter запустили «Показать ещё», получили тестовый `503`, повторили запрос с тем же курсором и получили последнюю страницу. При запуске обоих запросов фокус переходил на «Обновить». При ответе он оставался там или на фильтре, если пользователь сам перешёл на него клавишей Tab. Ранее загруженные события сохранились, после успешного повтора добавились новые, кнопка «Показать ещё» исчезла. Проверка покрывает клавиатурное поведение компонента с тестовыми ответами API. Условия IMP-07 и #226 действуют.

Ту же последовательность закрепили в [Playwright-наборе доступности](../../frontend/intelligence-trade-web/e2e/accessibility.spec.ts). На Windows против штатного frontend из изолированного Compose с реальным входом через Identity прошли 4/4 сценария при 320 CSS px: два в `chromium` и два в `mobile-webkit`. Ответы подменялись только для чтения бизнес-данных. Для продолжения истории тест проверяет достижимость кнопок через Tab, переход фокуса при Enter и сохранение выбора пользователя после ответа. Проверка относится к пагинации. Результаты full-stack realtime recovery и обязательного HTTPS gate учитываются отдельно по [Amendment для PR #232](https://github.com/vbondarev/intelligence.trade.system/issues/225#issuecomment-7113108623).

## Повторная проверка FIX-11–FIX-15

- FIX-11 подтверждает снятие защищённого снимка после `403` проверки сессии на паузе, сохранение полного logout и сохранение снимка при временном `503`. Поздний отказ после отмены проверки или смены пользователя не меняет текущую сессию.
- FIX-12 проверяет различимые OHLC и Stop Loss для значений порядка `10⁻⁹` в доступных таблицах. Узкий экран проверяется с ценами порядка `10⁻²⁰` и клавиатурной прокруткой внутри области таблицы.
- FIX-13 проверяет срок действия оценки и рекомендации по времени применения нового снимка на паузе, заморозку прежнего снимка и возврат к текущему времени после возобновления.
- FIX-14 проверяет сохранение ручной страницы поиска, ошибку её запроса, отмену ожидания и смену символа при возобновлении.
- FIX-15 проверяет успешный третий GET после двух сетевых отказов, ограниченное число попыток и отмену отложенных повторов. Проверки отказов авторизации сохранены.

Браузерная проверка длительной загрузки истории ждёт готовности realtime до открытия панели. Это не даёт стартовому recovery подменить GET, ответ которого удерживает тест. Проверки видимого статуса, live region, ограничения анимации и режима уменьшенного движения сохранены.

Итоговый SHA и журналы полного Windows и Linux recovery фиксируются в [PR #227](https://github.com/vbondarev/intelligence.trade.system/pull/227). Остатки ручной проверки и обязательный Windows WebKit gate остаются в приёмке.
