# G-08 — повторный аудит 26 критериев WCAG 2.2 A/AA

Рабочее дерево `task/225-web-accessibility` после Amendment о паузе автообновлений. Проверка охватила все 26 строк, ранее имевших статус `PARTIAL`. Статус указан для области каждой строки в [матрице](g08-wcag22-aa-matrix.md). Основа — [Issue #225](https://github.com/vbondarev/intelligence.trade.system/issues/225) и [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

## Как проверяли

- На Windows с Playwright 1.63.0 использовали Chromium и mobile WebKit с профилем iPhone 13. Авторизация проходила через настоящий локальный BFF и Identity. Для воспроизводимых портфеля, позиции, истории и ошибок API использовали синтетические ответы. Отдельный прогон realtime работал с реальными SignalR, outbox, REST и PostgreSQL.
- В браузерах проверили дерево доступности, HTML-связи и порядок чтения, правила axe WCAG A/AA и `label-content-name-mismatch`, фокус при последовательном Tab, Escape, возвращение фокуса после отмены, геометрию целей и отмену клика отпусканием вне элемента. В двухмерной таблице мерили габариты внешней страницы отдельно от внутренней прокрутки.
- Для `1.4.12` при 320 CSS px задали высоту строки 1,5, отступ после абзаца 2em, межбуквенный интервал 0,12em и межсловный 0,16em. В Chromium задали настоящий page zoom 400% и получили 314 CSS px на публичной странице, форме Identity, обзоре, подключениях и позиции. На этом проходе зарегистрировали 48 переходов Tab. При замере сразу после Tab WebKit иногда ещё прокручивал страницу. Повторный замер после прокрутки подтвердил видимость проверенных целей. Ранее зафиксированные результаты NVDA сохранены в матрице. В этом проходе снимки дерева доступности показывают, что браузер передал вспомогательной технологии.

## Навигация и формы

- В обоих браузерах нашли BTCUSDT просмотром списка и через форму «Символ». Поиск выдаёт ссылку в пределах выбранного подключения и режима списка. Две позиции с одинаковыми символом, размером и стороной имели одинаковое доступное имя `BTCUSDT · 0,15 LONG` при разных URL. Внутри каждой карточки доступны свои цена входа и валюта в списке определений. Отдельной программной связи этих сведений со ссылкой нет. Эти наблюдения добавлены к `2.4.4` и `2.4.5`. [Поиск как способ навигации](https://www.w3.org/WAI/WCAG22/Techniques/general/G161) · [Контекст ссылки](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html)
- Проверили неверный пароль, пустое после нормализации название, переименование, замену ключей, восстановление, нативное подтверждение отключения, пустой список, недоступную позицию, ошибки HTTP 503 списка и истории. На синтетических ответах управления подключением проверили HTTP 400 для отклонённых ключей, HTTP 403, HTTP 409 и HTTP 503. Сообщения выведены текстом. Для отклонённых ключей названы оба поля, для конфликта и недоступности предложен повтор. Охват всех известных полей и комбинаций ошибок отражён в `3.3.1` и `3.3.3`.
- На форме Identity отпускание указателя вне кнопки дало 0 POST. В формах и фильтрах проверили нативные `click`, `submit` и изменения значения. Диалог предупреждения о сессии позволяет выйти через Escape. Отмена переименования возвращает фокус к открывшей форме кнопке. На 320 CSS px измерения целей не выявили пересечения зон допуска. Логотип TradingView около 35×19 CSS px проходит по расстоянию.
- Повторный замер предупреждения сессии выполнили после завершения анимации Mantine при `opacity=1`. Axe не выявил нарушения контраста в обоих браузерах. При нормативных текстовых отступах ширина диалога и его содержимого составила 288 CSS px при viewport 320 CSS px.

## Регрессия и приёмка

- Полный браузерный E2E — **88 PASS, 11 SKIP по конфигурации, 1 FAIL**. Realtime recovery — **6/6**, включая паузу.
- Обязательный Windows HTTPS gate — **3 PASS, 1 FAIL**. В Windows mobile WebKit при cross-site запросе сервер получил реальную session cookie и контрольную cookie. Серверный заголовок содержит `SameSite=Lax`. Штатный браузерный E2E также сообщает `SameSite=None`.
- Все критерии IMP-01–IMP-07 действуют. Статус Issue #225 — `BLOCKED_BY_VERIFICATION`. Открытые результаты WCAG и обязательный Windows WebKit gate отражены в [аудите приёмки](g08-acceptance-audit.md).
