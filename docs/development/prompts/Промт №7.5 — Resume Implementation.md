
Продолжи ранее остановленную реализацию текущего GitHub Issue проекта `vbondarev/intelligence.trade.system`.

Принятые человеком решения зафиксированы в GitHub. Изменения WHAT и/или Approved Plan Amendments опубликованы и проверены.

Используй актуальные `AGENTS.md` и workflow `.agents/skills/trade-system-delivery/SKILL.md`.

**Твоя роль — coding-agent, технический исполнитель.**

## 1. Восстановление состояния

Перед продолжением:

1. Получи текущий GitHub Issue.
2. Прочитай актуальный WHAT.
3. Получи Base Approved Implementation Plan.
4. Получи все действующие Approved Plan Amendments.
5. Проверь канонические permalink и доверенное авторство.
6. Восстанови effective HOW.
7. Прочитай применимые инструкции репозитория.
8. Проверь текущее состояние своей рабочей ветки и связанного PR.
9. Определи, какие утверждённые шаги IMP уже выполнены, а какие требуют продолжения или корректировки согласно Amendment.

Если действующий HOW невозможно восстановить или он противоречив — STOP.

Не выбирай альтернативное техническое решение.

## 2. Продолжение исполнения

Работай в существующей ветке задачи, если утверждённый план не предусматривает иного.

Продолжи реализацию согласно обновлённому effective HOW.

Выполни предусмотренные изменения, необходимые тесты, документацию и проверки.

Если Amendment заменяет ранее реализованное поведение, приведи затронутый код к утверждённому новому поведению.

Не перепроектируй решение.

Не расширяй scope.

Не изменяй WHAT или HOW.

Если выполнение нового утверждённого решения невозможно, остановись и представь фактический отчёт о препятствии.

## 3. Проверки и Git

После выполнения:

- проведи основной self-review полного diff;
- выполни применимые тесты и сборку;
- синхронизируй предусмотренную документацию;
- проведи финальный self-review;
- создай commit и push по действующим правилам;
- создай или обнови соответствующий Draft PR;
- внеси в PR description ссылки на Base Plan и все действующие Amendments;
- проведи PR sanity check.

Не представляй предыдущие CI и External Review как доказательство корректности нового HEAD.

## 4. Результат

Верни:

- Issue и effective HOW;
- список действующих Amendments;
- продолженные и завершённые шаги IMP;
- выполненные изменения;
- результаты тестирования;
- commit SHA;
- итоговый HEAD SHA;
- ссылку на Draft PR;
- оставшиеся препятствия, если есть.

Не принимай новые архитектурные решения.

Не выполняй независимый External Review.

Не закрывай Issue.

Не выполняй merge.

После выполнения остановись и передай результат для независимого External Review или Re-review ChatGPT.

## Что дальше в ответе

В конце ответа выбери одно ближайшее действие по фактическому результату и учти уже выполненные шаги и явные разрешения. Используй одно поле: **Что написать дальше** для готовой команды, **Твоё решение** для выбора владельца, **Действие в GitHub** для ручного шага, **Ждём** для конкретного события или **Завершено** для подтверждённого результата. В команде укажи объект, существенную версию, ожидаемый результат и точку остановки. Для ожидания или ручного действия дай условие продолжения и команду повторной сверки, если она нужна. Помещай подсказку после результата, за пределами публикуемого артефакта и задания исполнителю. Подсказка служит текстом для владельца, полномочия определяет его поручение.

После возобновления укажи первый незавершённый IMP, а после публикации результата — нужную независимую проверку по №8 или №10. Если продолжение заблокировано, укажи конкретное препятствие и источник по №7.1.
