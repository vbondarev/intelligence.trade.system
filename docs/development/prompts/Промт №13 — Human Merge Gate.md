# №13 — Human Merge Gate

Подготовь решение владельца о ручном слиянии конкретного PR. Используй актуальный результат `READY_FOR_HUMAN_MERGE_GATE` из №12 и проверенную карточку ожидаемого результата.

## 1. Подтверди действительность допуска

Установи PR, Issue, целевую ветку, HEAD/BASE, effective HOW либо основание `N/A`, применимое независимое ревью и результат №12. Для `N/A` проверь указанное в №12 основание по `trade-system-pr-review`, включая ссылку на разрешение владельца. Сверь с GitHub текущие SHA, CI, approvals, reviews, threads, Draft, branch protection и mergeability.

Проверь, что доказательство по каждому затронутому пункту ROADMAP относится к версии, которую предстоит слить. Если проверенное состояние сохранилось, используй результат №12 без повторного полного аудита.

Если изменились HEAD или BASE, вернись к №12 для определения объёма перепроверки. Если изменение затрагивает ROADMAP, в обновлённом заключении должна быть подтверждена основная строка и связанные сводки для новой пары. При другом существенном препятствии укажи соответствующий этап возврата.

## 2. Покажи владельцу результат решения

Представь кратко:

- какой PR и в какую ветку предстоит слить;
- для каких HEAD/BASE действует допуск;
- какой объём окажется в целевой ветке;
- какие конкретные пункты ROADMAP будут завершены и что останется открытым;
- должен ли Issue закрыться или остаться открытым и почему;
- есть ли критерий, который по утверждённым правилам проверяется после merge, и кто отвечает за следующее действие.

## 3. Установи решение владельца

Если явное разрешение уже дано и охватывает проверенные PR, ветку, версию и действие, укажи источник и оставшееся ручное действие. Если разрешения нет или его границы неясны, запроси решение для конкретного состояния.

Итог:

- `HUMAN_MERGE_GATE_READY` — допуск подтверждён, ожидается решение владельца.
- `HUMAN_MERGE_APPROVED` — владелец явно разрешил слияние проверенного состояния.
- `HUMAN_MERGE_GATE_BLOCKED` — есть установленное препятствие.
- `HUMAN_MERGE_GATE_UNVERIFIED` — действительность допуска или границы решения установить невозможно.

Перед ручным слиянием владелец проверяет, что GitHub допускает действие и проверенное состояние сохранилось. Факт состоявшегося merge подтверждает GitHub. Если владелец также поручил дождаться merge и выполнить №14, координатор сохраняет PR, Issue, ветку, точную пару, результат №12, решение №13, карточку №11 и разрешённый объём №14. Покажи ручное действие и наблюдай GitHub в текущем проходе. При смене пары до merge остановись и вернись к применимой перепроверке. После подтверждённого `merged=true` в согласованную ветку передай доказательства и поручение в №14. Если ожидание истекло или переход не поручен, сообщи состояние и условие продолжения.

Не изменяй документы, метаданные и статусы GitHub. Merge и закрытие Issue выполняются в пределах отдельного решения владельца.

## Что дальше в ответе

В конце ответа выбери одно ближайшее действие по фактическому результату и учти уже выполненные шаги и явные разрешения. Используй одно поле: **Что написать дальше** для готовой команды, **Твоё решение** для выбора владельца, **Действие в GitHub** для ручного шага, **Ждём** для конкретного события или **Завершено** для подтверждённого результата. В команде укажи объект, существенную версию, ожидаемый результат и точку остановки. Для ожидания или ручного действия дай условие продолжения и команду повторной сверки, если она нужна. Помещай подсказку после результата, за пределами публикуемого артефакта и задания исполнителю. Подсказка служит текстом для владельца, полномочия определяет его поручение.

Если допуск актуален, а решения владельца ещё нет, покажи **Твоё решение** с формулировкой разрешения на слияние конкретной пары HEAD/BASE. После явного решения покажи **Действие в GitHub** для ручного merge. Если ожидание и №14 уже поручены, продолжи по событию в том же проходе. Иначе дай команду на №14 после merge. Если допуск устарел, укажи проверку, к которой нужно вернуться.
