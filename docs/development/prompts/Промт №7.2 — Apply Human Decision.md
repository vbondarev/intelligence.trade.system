
Прими моё последнее явное решение по результатам STOP Analysis для текущего Issue проекта `vbondarev/intelligence.trade.system`.

Подготовь изменения утверждённых источников, необходимые для выполнения решения владельца и продолжения прерванного действия.

**Ты (ChatGPT) отвечаешь за технический анализ и подготовку изменений.**

Я утверждаю продуктовые и архитектурные решения.

Coding-agent не участвует в подготовке WHAT/HOW.

## 1. Проверка принятого решения

Восстанови:

- текущий Issue;
- Base Approved Implementation Plan;
- действующие Amendments;
- последний STOP Analysis;
- принятое мной решение;
- прерванный этап, действие и связанный IMP, finding, FIX или DOC, если применимо;
- затронутые архитектурные ограничения.

Убедись, что выбранный вариант определён однозначно.

Не подменяй моё решение собственной рекомендацией.

Если решение недостаточно определено для корректного изменения WHAT/HOW, укажи конкретный неразрешённый вопрос.

## 2. Изменение WHAT

Если принятое решение меняет требования:

1. Определи точные разделы GitHub Issue, которые требуется изменить.
2. Подготовь новую согласованную редакцию затронутых требований.
3. Обнови связанные Acceptance Criteria.
4. Уточни scope и out-of-scope, если необходимо.
5. Определи необходимые изменения тестирования.
6. Сохрани все не затронутые решением требования.
7. Проверь отсутствие противоречий.

Представь точные изменения Issue для моего утверждения.

Не публикуй их автоматически.

Если изменение WHAT влияет на существующий Approved Plan, определи соответствующие изменения HOW.

## 3. Изменение HOW

Если решение меняет утверждённый HOW, подготовь Approved Plan Amendment. Укажи, какие положения заменены, какие сохраняют силу и какое действие сможет продолжиться после публикации.

Используй текущий Base Approved Plan и все действующие Amendments.

Amendment должен содержать:

- связанный Issue;
- основание и принятое Human Decision;
- ссылку на Base Approved Implementation Plan;
- ссылки на предшествующие применимые Amendments;
- точные положения, которые заменяются;
- новую редакцию заменяемых положений;
- положения, которые дополняются;
- положения, которые остаются без изменений;
- последствия для шагов IMP;
- последствия для декомпозиции PR;
- изменения алгоритмов, компонентов и контрактов;
- необходимые тесты;
- изменения документации;
- новые или изменённые STOP-условия;
- условия и порядок продолжения прерванного действия.

Первая строка будущего канонического комментария:

`# Approved Implementation Plan — Amendment`

До утверждения Amendment имеет статус `PROPOSED`, независимо от подготовленного канонического заголовка.

Не переписывай полный Base Approved Plan.

Не изменяй предыдущие Amendments.

Не добавляй изменения, выходящие за рамки моего решения.

## 4. Если меняются WHAT и HOW

Подготовь оба артефакта в следующем порядке:

1. Предлагаемая редакция Issue.
2. Анализ влияния нового WHAT на действующий HOW.
3. Проект Approved Plan Amendment.
4. Проверка согласованности обоих изменений.

Публикация WHAT должна предшествовать публикации изменённого HOW.

Если после изменения Issue обнаруживается новое противоречие, остановись и представь его мне до публикации Amendment.

## 5. Проверка effective HOW

Восстанови предполагаемый effective HOW после применения подготовленных изменений.

Проверь:

1. Соответствие действующему или предлагаемому утверждённому WHAT.
2. Отсутствие противоречий с ADR/contracts.
3. Явную область действия нового Amendment.
4. Однозначность заменённых и сохранённых положений.
5. Совместимость с предыдущими Amendments.
6. Корректность последовательности IMP.
7. Влияние на уже завершённые шаги.
8. Достаточность проверок.
9. Отсутствие несогласованного расширения scope.
10. Возможность дальнейшего исполнения coding-agent без выбора архитектурных альтернатив.

Если старый Amendment содержит параметры алгоритма, который заменяется новым решением, явно установи дальнейшую применимость этих параметров.

Не оставляй неоднозначных superseded-положений.

## 6. Полный результат

Представь:

1. Принятое Human Decision.
2. Его техническое обоснование и последствия.
3. Проект изменений Issue, если применимо.
4. Полный текст предлагаемого Approved Plan Amendment, если применимо.
5. Перечень заменённых, дополненных и сохранённых положений.
6. Затронутые IMP/PR.
7. Изменения тестирования и документации.
8. Результаты самопроверки.
9. Вопросы, если они остаются.

Итоговый статус:

- `READY_FOR_HUMAN_GATE` — изменения полностью подготовлены.
- `BLOCKED_BY_HUMAN_DECISION` — необходимо дополнительное решение.
- `BLOCKED_BY_MISSING_DATA` — отсутствуют критические данные.
- `BLOCKED_BY_SOURCE_CONFLICT` — не удалось согласовать источники WHAT/HOW.

### Что дальше в ответе

В конце ответа выбери одно ближайшее действие по фактическому результату и учти уже выполненные шаги и явные разрешения. Используй одно поле: **Что написать дальше** для готовой команды, **Твоё решение** для выбора владельца, **Действие в GitHub** для ручного шага, **Ждём** для конкретного события или **Завершено** для подтверждённого результата. В команде укажи объект, существенную версию, ожидаемый результат и точку остановки. Для ожидания или ручного действия дай условие продолжения и команду повторной сверки, если она нужна. Помещай подсказку после результата, за пределами публикуемого артефакта и задания исполнителю. Подсказка служит текстом для владельца, полномочия определяет его поручение.

Для готовой редакции поправки покажи **Твоё решение** с фразой утверждения этой редакции по №7.3. Если решение ещё не определяет обязательную часть изменения, назови конкретный открытый выбор или требуемый источник.
