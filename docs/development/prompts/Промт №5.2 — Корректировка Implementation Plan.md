
Внеси согласованные корректировки в текущий Implementation Plan проекта `vbondarev/intelligence.trade.system`.

Используй мои последние замечания, результаты Human Plan Review, связанный GitHub Issue и действующие архитектурные ограничения.

**Твоя роль — технический архитектор.**

Ты самостоятельно анализируешь влияние замечаний на HOW и подготавливаешь исправленную полную редакцию плана.

Я принимаю новые существенные архитектурные и продуктовые решения.

Coding-agent не участвует.

## 1. Анализ корректировок

Для каждого замечания:

1. Определи затронутые разделы.

2. Установи первопричину недостатка плана.

3. Определи необходимое техническое изменение.

4. Проверь соответствие WHAT.

5. Оцени последствия для архитектуры, компонентов и контрактов.

6. Определи влияние на шаги IMP, PR, тесты и документацию.

7. Установи необходимость Human Decision.


Не добавляй новые требования и не расширяй scope.

Если исправление требует нового архитектурного решения, представь варианты и останови соответствующую корректировку до моего решения.

## 2. Переработка HOW

Внеси согласованные изменения в Implementation Plan.

При необходимости скорректируй:

- архитектурную модель;

- взаимодействие компонентов;

- алгоритмы и обработку состояний;

- технические шаги IMP;

- зависимости между шагами и PR;

- тестовые сценарии;

- критерии завершения;

- документацию;

- риски и STOP-условия;

- ограничения coding-agent.


Сохрани все ранее утверждённые решения, которые не затрагиваются корректировками.

Не выполняй несвязанный рефакторинг содержания плана.

## 3. Обновление версии

Подготовь новую полную редакцию Implementation Plan.

Увеличь версию по последовательному соглашению документа.

Укажи:

- номер Issue;

- предыдущую версию;

- новую версию;

- исследованный HEAD;

- статус `PROPOSED`;

- краткую историю изменений.


Обнови весь документ, а не только затронутые фрагменты.

Новая редакция должна быть самодостаточной и не зависеть от текста предыдущего чата.

## 4. Повторная техническая самопроверка

Проверь:

1. Все согласованные замечания устранены.

2. Изменения не создали новых противоречий.

3. Все требования Issue покрыты.

4. Архитектурные решения согласованы.

5. Технические шаги исполнимы.

6. Тестирование соответствует обновлённому HOW.

7. Последовательность PR корректна.

8. Матрица `WHAT → IMP → Tests` обновлена.

9. Coding-agent не должен принимать самостоятельные существенные технические решения.

10. Нет несогласованных изменений WHAT/HOW.


Если появились новые блокирующие вопросы, вынеси их на моё рассмотрение.

## 5. Результат

Представь:

1. Полный обновлённый Implementation Plan.

2. Новую версию плана.

3. Перечень внесённых изменений.

4. Результат повторной самопроверки.

5. Оставшиеся замечания и вопросы.

6. Итоговый статус.


Статусы:

- `READY_FOR_HUMAN_GATE`

- `REVISION_REQUIRED`

- `BLOCKED_BY_HUMAN_DECISION`

- `BLOCKED_BY_MISSING_DATA`


Не утверждай план самостоятельно.

Не публикуй его в GitHub.

Не изменяй код и документацию.

Не передавай задачу coding-agent.

Не начинай implementation.

После подготовки новой редакции остановись.

В конце ответа выбери одно ближайшее действие по фактическому результату и учти уже выполненные шаги и явные разрешения.
