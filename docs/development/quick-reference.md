# Шпаргалка по процессу разработки

Если ближайший шаг неясен, напиши `$next-stage по текущей задаче`. Для заданного объекта используй `$next-stage Issue #237` или `$next-stage PR #195`. Добавь «подготовь задание», чтобы получить полный текст для передачи исполнителю и короткую команду для текущего чата. [Обзор процесса](README.md) · [Правила next-stage](../../.agents/skills/next-stage/SKILL.md)

Ответ заканчивается одним из пяти полей.

| Поле | Что делать |
|---|---|
| **Что написать дальше** | Отправь готовую команду в текущем чате. |
| **Твоё решение** | Выбери предложенный вариант или явно утверди указанную редакцию. Публикацию и исполнение разрешай в пределах нужного действия. |
| **Действие в GitHub** | Открой указанный объект и выполни ручное действие. Если дана команда сверки, отправь её после выполнения. |
| **Ждём** | Дождись указанного события или результата CI, затем отправь команду сверки. |
| **Завершено** | Результат по запрошенному объекту подтверждён. Для частичного PR проверь остаток родительской Issue отдельно. |

## Подготовка задачи

| Когда | Пример команды |
|---|---|
| Нужно изучить задачу | «Проведи Discovery по №1 и покажи выводы и открытые вопросы». Для одного вопроса попроси целевую проверку. |
| Требуется решение по WHAT | «Разбери вопрос D-… по №2 и покажи варианты и последствия». После ответа зафиксируй свой выбор. |
| WHAT согласован | «Подготовь черновик GitHub Issue по №3. Покажи его здесь». |
| Черновик устраивает | «Утверждаю эту редакцию Issue. Опубликуй её по №3.1 и проверь результат». |
| Issue опубликована | «Подготовь Implementation Plan по №4 для Issue #… Покажи план здесь. Пока не публикуй и не начинай реализацию». |
| План готов | «Проверь план v… для #… по №5.1». При замечаниях поручить конкретную корректировку по №5.2. |
| План готов к утверждению | «Утверждаю план v… для #… по №5.3». Для публикации добавить «Разрешаю опубликовать именно эту редакцию по №5.4». |
| План опубликован | «Начинай реализацию #… по утверждённому плану [permalink]. Проведи проверки и подготовь Draft PR в develop». |

## Реализация, STOP и ревью

| Когда | Пример команды |
|---|---|
| Работу блокирует препятствие | «Разбери по №7.1 препятствие для [действие по Issue или PR]. Источник — [finding, CI, сравнение SHA или положения документов]. Покажи условие возврата». |
| Возможен локальный FIX | «Выполни локальное исправление из отчёта №7.1 для #… Сверь результат и назови первое оставшееся действие». |
| Требуется поправка к плану | «Выбираю [вариант]. Подготовь редакцию поправки по №7.2». После проверки утвердить её по №7.3 и разрешить публикацию по №7.4. |
| Поправка проверена | Вернись к первому оставшемуся действию. Для остановленной реализации — «Продолжи IMP… по №7.5». Для опубликованного FIX — независимая проверка по №10. |
| PR готов к первичному ревью | «Проведи №8 для PR #… на актуальных HEAD/BASE». |
| Есть подтверждённые замечания | «Спроектируй FIX для [finding] по №9, режим А» либо «Подготовь задание по согласованным FIX по №9, режим Б». Исполнение готового задания поручается отдельно. |
| FIX опубликованы или изменилось проверенное состояние | «Проведи №10 для PR #… на актуальных HEAD/BASE». Вход А для опубликованных FIX, вход Б для существенного изменения без FIX при установленном исходном ревью. |

## Допуск и слияние

| Когда | Пример команды или действие |
|---|---|
| Техническое ревью пройдено | «По №11 подготовь документацию и карточку ожидаемых статусов PR, Issue и пунктов ROADMAP для PR #…». При необходимости отдельно разреши документальные правки. |
| Документация готова | «Проверь готовность PR #… по №12 на актуальных HEAD/BASE». Для документальной дельты проверь применимость §4B. |
| Ожидается CI | Дождись указанного запуска. Затем «Обнови проверку №12 для PR #… по запуску [ссылка]». |
| Draft блокирует слияние | Сними Draft, когда будешь готов к этому шагу. Затем «Обнови проверку №12 для PR #… после снятия Draft». |
| Допуск положительный | «Подготовь Human Merge Gate по №13 для PR #…». При согласии явно разреши merge проверенных HEAD/BASE и выполни его вручную в GitHub. |
| PR слит | «Выполни №14 для PR #… Проверь результат в develop, post-merge CI, Issue и пункты ROADMAP». |
| После merge остался критерий или расходится ROADMAP | «Укажи конкретное расхождение из отчёта №14 и подготовь точное исправление для согласования». При частичной поставке используй `$next-stage Issue #…`. |
