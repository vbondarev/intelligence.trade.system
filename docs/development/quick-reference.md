# Шпаргалка по процессу разработки

Если ближайший шаг неясен, напиши `$next-stage по текущей задаче`. Для заданного объекта используй `$next-stage Issue #237` или `$next-stage PR #195`. Добавь «подготовь задание», чтобы получить полный текст для передачи исполнителю. Для отдельного этапа в текущем чате помощник также даёт короткую команду. Для совмещённого поручения копируй один полный блок целиком. [Обзор процесса](README.md) · [Правила next-stage](../../.agents/skills/next-stage/SKILL.md)

Для передачи в новый чат напиши `$next-stage PR #… — подготовь задание для нового чата`. Отправь весь полученный блок целиком. В задании на №12 должны быть исходное ревью и карточка №11. [Правила передачи в новый чат](../../.agents/skills/next-stage/SKILL.md#81-передача-в-новый-чат)

## Пять точек участия

1. **Обсуди WHAT.** После Discovery помощник готовит черновик Issue.
2. **Утверди Issue.** Используй [команду от Issue к проверенному плану](#от-issue-к-проверенному-плану).
3. **Утверди план.** Используй [команду от плана к ручному Ready](#от-плана-к-ручному-ready-for-review).
4. **Нажми Ready for review вручную**, когда №12 подтвердит, что Draft — единственное препятствие. При порученном ожидании №12 завершит сверку в том же проходе.
5. **Прими финальное решение и выполни merge вручную.** Используй [команду от ручного merge к завершению Issue](#от-ручного-merge-к-завершению-issue). Перед merge сверь пару HEAD/BASE.

Для паузы напиши «Приостанови дальнейшие действия по #… и покажи подтверждённое состояние». Для узкого поручения укажи границу, например «Выполни только №11 в режиме чтения». При замечаниях координатор использует до двух циклов отдельно для плана и реализации и передаёт начатый пакет вместе с остатком лимита. [Правила координации](README.md#работа-между-решениями-владельца)

## Команды на весь отрезок

Используй фактически подтверждённые объект, редакцию, labels и пару HEAD/BASE. Если часть работы завершена, начинай команду с первого оставшегося действия. При явной паузе или поручении только на один этап соблюдай указанную границу.

### От Issue к проверенному плану

> Утверждаю эту редакцию Issue и указанные labels. Опубликуй и сверь Issue. Подготовь Implementation Plan и организуй его независимую проверку. При замечаниях в пределах согласованного WHAT доработай план и проведи независимую перепроверку в пределах двух циклов исправлений. Представь точную редакцию для моего утверждения. Если раньше потребуется моё решение, остановись и назови конкретный вопрос.

Для опубликованного и сверенного Issue начни с «Для Issue #… подготовь Implementation Plan и организуй его независимую проверку». Если план уже подготовлен, назови точную редакцию и начни с оставшейся проверки или доработки.

### От плана к ручному Ready for review

> Утверждаю Implementation Plan v… для Issue #…. Опубликуй и сверь эту редакцию, реализуй план и подготовь Draft PR. Дождись обязательного CI и организуй независимое ревью. Разрешаю подтверждённые исправления и документальные правки в пределах утверждённого плана и двух циклов исправлений реализации. Проверь документальную готовность и условия допуска к слиянию. Если останется только Draft, сообщи проверенную пару HEAD/BASE, дождись моего ручного **Ready for review** и заверши финальную сверку в том же проходе. Остановись перед решением о слиянии или раньше, если потребуется моё решение.

Для уже утверждённого плана начни с публикации. Для опубликованного и сверенного плана начни с реализации и укажи проверенный permalink. Если исправленная редакция ждёт независимой перепроверки, первым действием укажи перепроверку уже учтённого пакета. При положительном результате предложи утверждение точной редакции или используй уже выданное утверждение и условное поручение на публикацию и исполнение этой редакции.

### От ручного merge к завершению Issue

> Разрешаю ручное слияние PR #… в `develop` на HEAD `…` и BASE `…`. Подтверди допуск и дождись, пока я солью PR вручную. После подтверждения слияния в GitHub проверь полную поставку, ROADMAP и дождись обязательного post-merge CI для коммита слияния. Если все условия закрытия выполнены и Issue #… открыт, разрешаю закрыть его как `completed`. Перечитай Issue и сообщи итог.

Для уже слитого PR начни с «Проверь результат слияния PR #… в `develop`». Оставь применимые постпроверки, ожидание CI и условное закрытие конкретного Issue.

## Ответ помощника

Ответ заканчивается одним из пяти полей.

| Поле | Что делать |
|---|---|
| **Что написать дальше** | Отправь готовую команду в текущем чате. |
| **Твоё решение** | Выбери предложенный вариант или явно утверди указанную редакцию. Публикацию и исполнение разрешай в пределах нужного действия. |
| **Действие в GitHub** | Открой указанный объект и выполни ручное действие. Если дана команда сверки, отправь её после выполнения. |
| **Ждём** | Указано событие и условие продолжения. Если поручено дождаться CI или ручного снятия Draft, №12 продолжит проверку в том же проходе. |
| **Завершено** | Результат по запрошенному объекту подтверждён. Для частичного PR проверь остаток родительской Issue отдельно. |

## Подготовка задачи

| Когда | Пример команды |
|---|---|
| Нужно изучить задачу | «Проведи Discovery по №1 и покажи выводы и открытые вопросы». Для одного вопроса попроси целевую проверку. |
| Требуется решение по WHAT | «Разбери вопрос D-… по №2 и покажи варианты и последствия». После ответа зафиксируй свой выбор. |
| WHAT согласован | «Подготовь черновик GitHub Issue по №3. Покажи его здесь». |
| Черновик устраивает | Используй [команду от Issue к проверенному плану](#от-issue-к-проверенному-плану) с утверждением точной редакции и labels. |
| `ISSUE_PUBLISHED_VERIFIED`, `N/A` применим и явно разрешён владельцем | Когда готов начать, напиши: «Начинай реализацию Issue #… по №6 на основании Issue и разрешения `N/A` [ссылка]. Выполни проверки и подготовь Draft PR в develop». |
| `ISSUE_PUBLISHED_VERIFIED`, Issue подходит для `N/A`, решения ещё нет | Выбери, разрешаешь ли ты `N/A` для этого Issue или поручаешь подготовить обычный план по №4. |
| `ISSUE_PUBLISHED_VERIFIED`, обычный маршрут с планом | Используй [команду от Issue к проверенному плану](#от-issue-к-проверенному-плану). Начни с подготовки плана или первой оставшейся проверки. Если план уже утверждён, начни с оставшегося действия по [следующей команде](#от-плана-к-ручному-ready-for-review). |
| Полная редакция плана ожидает проверки | Используй [команду от Issue к проверенному плану](#от-issue-к-проверенному-плану) с проверки точной редакции до её представления владельцу. |
| Редакция проверена, `READY_FOR_HUMAN_GATE`, в том числе после независимой перепроверки | Используй [команду от плана к ручному Ready](#от-плана-к-ручному-ready-for-review) с утверждением точной редакции. |
| Утверждённый план опубликован и проверен, поручение на реализацию ещё не дано | Используй [команду от плана к ручному Ready](#от-плана-к-ручному-ready-for-review) с реализации по проверенному permalink. |

Если состояние плана или поправок неизвестно, сначала сверь их по Issue. При конкретном непроверенном основании после №5.2 или по просьбе владельца повтори №5.1.

## Реализация, STOP и ревью

| Когда | Пример команды |
|---|---|
| Работу блокирует препятствие | «Разбери по №7.1 препятствие для [действие по Issue или PR]. Источник — [finding, CI, сравнение SHA или положения документов]. Покажи условие возврата». |
| Возможен локальный FIX | «Выполни локальное исправление из отчёта №7.1 для #… Сверь результат и назови первое оставшееся действие». |
| После STOP задача больше не подходит для `N/A`, решение владельца принято, опубликованный WHAT подтверждён, первый план ещё предстоит подготовить | «Подготовь первый Implementation Plan по №4 для Issue #… с учётом решения [ссылка]. Покажи план здесь. Пока не публикуй его и не возобновляй реализацию». Если решение ещё не отражено в Issue, сначала согласуй или проверь разрешённое обновление WHAT. |
| Требуется поправка к действующему базовому плану | «Выбираю [вариант]. Подготовь редакцию поправки по №7.2». После проверки утвердить её по №7.3 и разрешить публикацию по №7.4. |
| Локальное исправление проверено | Вернись к первому оставшемуся действию. Если была остановлена реализация, продолжи конкретный IMP по №7.5 в рамках действующего основания. |
| Поправка проверена | Вернись к первому оставшемуся действию. Для остановленной реализации — «Продолжи IMP… по №7.5». Для опубликованного FIX — независимая проверка по №10. |
| PR готов к первичному ревью | «Проведи №8 для PR #… на актуальных HEAD/BASE». |
| Есть подтверждённые замечания | «Спроектируй FIX для [finding] по №9, режим А» либо «Подготовь задание по согласованным FIX по №9, режим Б». Готовое задание исполняется только по явному поручению, включая ранее выданное применимое разрешение на FIX. |
| FIX опубликованы или изменилось проверенное состояние | «Проведи №10 для PR #… на актуальных HEAD/BASE». Вход А для опубликованных FIX, вход Б для существенного изменения без FIX при установленном исходном ревью. |

## Допуск и слияние

Для сведений о версии целевой ветки, BASE события и проверенном кандидате используй [«Версии и CI»](../../.agents/skills/trade-system-pr-review/SKILL.md#версии-и-ci).

| Когда | Пример команды или действие |
|---|---|
| Техническое ревью пройдено | «По №11 подготовь документацию и карточку ожидаемых статусов PR, Issue и пунктов ROADMAP для PR #… по приложенному отчёту №8 или №10». При необходимости отдельно разреши документальные правки. |
| Документация готова | «Проверь готовность PR #… по №12 на актуальных HEAD/BASE. Используй приложенные карточку №11 и исходный отчёт». Для изменения только документов после №11 при прежней BASE и сохранении WHAT/HOW и критериев приёмки используй §4B. |
| Ожидается обязательный CI, других препятствий помимо Draft не выявлено | «Дождись `ci-gate` запуска [ссылка] для PR #… и продолжи №12 на HEAD `…` и BASE `…`. Если останется только Draft, сообщи, когда нажать **Ready for review**, дождись моего действия и выполни финальную сверку в том же проходе. Остановись перед №13». |
| CI зелёный, Draft может быть единственным препятствием | «Проведи №12 для PR #… на актуальных HEAD/BASE. Если останется только Draft, сообщи проверенную пару и дождись, пока я нажму **Ready for review**. Затем перечитай GitHub, выдай итог и остановись перед №13». При смене пары №12 завершит проход без допуска. |
| Допуск положительный | Используй [команду от ручного merge к завершению Issue](#от-ручного-merge-к-завершению-issue) для проверенной пары. |
| PR слит | Используй [команду от ручного merge к завершению Issue](#от-ручного-merge-к-завершению-issue) с первого оставшегося действия после слияния. |
| После merge остался критерий или расходится ROADMAP | «Укажи конкретное расхождение из отчёта №14 и подготовь точное исправление для согласования». При частичной поставке используй `$next-stage Issue #…`. |
