# Процесс разработки Intelligence.TradeSystem

Для выбора ближайшего действия по задаче вызови `$next-stage PR #195`. Правила вызова описаны в [next-stage](../../.agents/skills/next-stage/SKILL.md).

## 1. Общая схема

№1 Discovery → №2 при открытых решениях по WHAT → №3 и №3.1 Issue → №4 план → №5.1–5.4 проверка, утверждение и публикация → №6 реализация → №8 независимое ревью.

При замечаниях: №9 подготовка FIX или задания → исполнение разрешённых FIX → №10 независимая перепроверка. При существенном изменении ранее проверенного состояния возможен №10 без нового FIX. После положительного применимого ревью: №11 документация → №12 допуск → №13 решение владельца и ручной merge → №14 проверка факта в целевой ветке.

STOP / Amendment — из этапа, на котором возникло препятствие. После разрешения вернись к прерванному действию с учётом уже выполненной работы.

## 2. Последовательность промтов

|№|Промт|Что делаем|Кто выполняет|
|---|---|---|---|
|**01**|Discovery|Исследуем следующую задачу из ROADMAP, код, требования, риски и архитектуру|ChatGPT|
|**02**|Human Decisions|Рассматриваем альтернативы и принимаем необходимые решения|ChatGPT + я|
|**03 / 03.1**|GitHub Issue (WHAT)|Готовим редакцию, после разрешения публикуем и проверяем её|ChatGPT + я|
|**04**|Implementation Plan (HOW)|Проектируем архитектуру, алгоритмы, шаги IMP, PR и тесты|ChatGPT|
|**05**|Human Plan Review + Gate|Проверяем, утверждаем и публикуем Implementation Plan в Issue|ChatGPT + я|
|**06**|Implementation|Coding-agent реализует утверждённый план, тестирует и создаёт Draft PR|Coding-agent|
|**07**|STOP / Amendment|Разбираем препятствия и согласовываем изменения WHAT/HOW|ChatGPT + я|
|**08**|External Review|Независимо проверяем код, архитектуру, тесты, CI и замечания Codex/Copilot|ChatGPT|
|**09**|Review Fixes|Проектируем конкретные исправления и передаём coding-agent|ChatGPT + я + coding-agent|
|**10**|Re-review|Независимо проверяем опубликованные FIX либо существенное изменение ранее проверенного состояния PR|ChatGPT|
|**11**|Pre-Merge Documentation|Обновляем ROADMAP и документы до целевого состояния после Merge|ChatGPT + coding-agent|
|**12**|Merge Readiness|Финально проверяем HEAD, CI, документацию, отзывы и mergeability|ChatGPT|
|**13**|Human Merge Gate|Вручную сливаем PR и закрываем Issue, если задача полностью завершена|Я|
|**14**|Post-Merge Verification|Проверяем состояние `develop` после Merge|ChatGPT|

При проверенной полной редакции №5.2 со статусом `READY_FOR_HUMAN_GATE` переходи к №5.3; новый проход №5.1 нужен при конкретном непроверенном основании или по просьбе владельца.

**Результат:** GitHub содержит утверждённые WHAT и HOW. Начало реализации определяется поручением владельца.

|Шаг|Что запускаю|Что ожидаю|

|13|[Ручной Merge](prompts/%D0%9F%D1%80%D0%BE%D0%BC%D1%82%20%E2%84%9613%20%E2%80%94%20Human%20Merge%20Gate.md)|Я сливаю PR в `develop`, затем при необходимости закрываю Issue|
|14|[Post-Merge Verification](prompts/%D0%9F%D1%80%D0%BE%D0%BC%D1%82%20%E2%84%9614%20%E2%80%94%20Post-Merge%20Verification.md)|Проверено, что код и документация действительно находятся в `develop`|

**Карточка №11–14:** PR, Issue, каждый затронутый пункт ROADMAP и ближайшее действие. №11 указывает ожидаемый статус, основную строку и сводки в HEAD. №12 проверяет их для результата слияния текущих HEAD/BASE. Если полностью выполненный пункт останется «в работе», итог — `NOT_READY`, возврат к точной DOC-правке по №11. №13 сохраняет привязку допуска к разрешённому состоянию. №14 сверяет факт merge, состояние Issue и строки ROADMAP на результирующем SHA и, если он изменился, на текущем HEAD целевой ветки. Завершённый PR может быть частью открытой Issue или этапа.

Если обязательный критерий проверяется только после merge, зафиксируй источник требования, промежуточный статус, событие, исполнителя и действие для завершения. Если на SHA слияния завершённый пункт помечен как незавершённый, это `POST_MERGE_DISCREPANCY`. Последующую перезапись в целевой ветке зафиксируй отдельно.

Если №11 изменил HEAD, №12 обязан независимо проверить его заново. Если №12 нашёл ошибку — возвращаемся к соответствующему этапу.

## 4. Кто за что отвечает

|Я|ChatGPT|Coding-agent|
|---|---|---|
|Утверждаю WHAT|Исследует требования|Читает WHAT|
|Принимаю архитектурные решения|Проектирует HOW|Исполняет HOW|
|Утверждаю план|Проверяет архитектуру и код|Пишет код и тесты|
|Согласовываю исправления|Устанавливает причины дефектов|Выполняет конкретные исправления|
|Разрешаю Merge|Проверяет готовность|Создаёт commits и PR|

**Правило:** coding-agent не выбирает новую архитектуру и не пересматривает утверждённый план. При серьёзном препятствии он останавливается.

## 5. Быстрые правила возврата

|Ситуация|Куда возвращаемся|
|---|---|
|Не согласованы требования|№02–03|
|Нужен пересмотр HOW до реализации|№04–05|
|При реализации, ревью или проверке возникло препятствие, которое требует разбора|№7.1 с прерванным действием и его источником|
|External Review выявил ошибки|№09|
|Re-review обнаружил новые дефекты|№09 → №10|
|Документация не соответствует коду|№11|
|После №11 изменились только документы|№12 §4B, если изменения сохраняют утверждённые WHAT/HOW и выполнены условия этой ветви|
|Изменился код после успешного Re-review|№10 → №11 → №12|
|CI или GitHub блокирует Merge|Исправление причины → повтор №12|
|После Merge обнаружено расхождение|№14 → отдельное исправление по характеру проблемы|
| Установлено, что первичного независимого ревью не было | №8 на текущем состоянии |
| Предыдущее ревью могло быть выполнено, но его охват или версия неизвестны | Восстановить источник. Если это невозможно, полный №8 может создать новое исходное ревью |
| Подтверждённое ревью устарело из-за смены BASE, effective HOW или технического поведения | №10, вход Б → учесть актуальность документации → №12 |
| В ходе проверки снова изменились HEAD или BASE | Зафиксировать последнюю пару, обновить объём и сверить её непосредственно перед вердиктом |
| Единственным препятствием был Draft и он снят по разрешению владельца | Обновить №12 → №13 с учётом области уже данного решения |

## 6. Главные правила процесса

1. **Issue = WHAT.** Что нужно реализовать.

2. **Approved Implementation Plan = HOW.** Как реализовать.

3. **Human Gate обязателен** для новых существенных решений.

4. **Coding-agent исполняет**, ChatGPT анализирует и проверяет.

5. **External Review и Re-review независимы** от self-review coding-agent.

6. **ROADMAP и документы до Merge отражают целевое состояние сразу после слияния.** Для критерия, проверяемого только после merge, укажи корректный промежуточный статус и последующее действие.

7. **Изменение HEAD, BASE или effective HOW требует сверки прежних выводов с актуальным состоянием.**

8. **Merge только вручную**, после подтверждённой готовности.

9. **Закрытие Issue отдельно от Merge**, если GitHub не закрыл его автоматически или задача состоит из нескольких PR.

10. **№14 проверяет фактический результат в `develop`.** Для завершения всей задачи подтверди обязательный объём, ожидаемое состояние Issue и конкретных пунктов ROADMAP.
